# 6-3단계: 전체 시험 집계 (코드만, 실행 보류)

> 94문제 전체 시험을 돌리고 **정답률·오답률·보류율·환각률**을 한 번에 집계하는 코드다.
> 시험 1회 비용(약 $0.60, 약 850원)과 개선 실험까지 포함한 총비용(약 5,000원)을 고려해 **실제 전체 시험은 실행하지 않았다.** 집계 코드는 이미 있는 5문제 결과로만 검증했다 (추가 비용 0).

## 한 일

| 파일 | 설명 |
|---|---|
| `src/bnb2/evaluate.py` | `to_row`(결과 한 줄), `summarize`(비율 계산), `run_summary`(Langfuse 실험 전체 점수), `print_summary`(비교 표), `report`(저장된 결과로 재집계) |
| `src/bnb2/__init__.py` | `uv run bnb2 report 이름` 명령 추가 |

## 지표 계산 (`summarize`)

| 지표 | 계산 |
|---|---|
| 정답률 | grade = correct 비율 |
| 부분정답률 | grade = partial 비율 |
| 오답률 | grade = wrong 비율 |
| 보류율 | grade = abstain 비율 ("찾지 못했어요", 담당자 판단) |
| 환각률 | hallucination = true 비율 |
| 검색 적중률 | retrieval_hit = true 비율 |
| 차단율 | blocked = true 비율 (근거 검사 노드가 막은 비율) |
| **종합 점수** | (정답률 + 0.5 × 부분정답률) × 100 |

종합 점수는 "1차 50점 → 개선 후 65점"처럼 **한 숫자로 비교**하려고 넣었다. partial을 0.5로 치는 건 임의의 기준이라 **정답률·환각률과 항상 함께** 본다.

**비교 기준(`BASELINE`)**: 기존 n8n 봇(`bnb`)의 마지막 시험 "프롬프트 개선 후" 결과를 넣어 두었다. 94문제, 같은 Sonnet 채점이다. 정답 34, 부분 29, 오답 9, 보류 22, 검색 적중 43.

## Langfuse에 남는 것

`run_experiment(..., run_evaluators=[run_summary])`
- **문제별 점수** (6-2와 같음): grade, hallucination, retrieval_hit, blocked
- **실험 전체 점수** (새로 추가): `correct_rate`, `partial_rate`, `wrong_rate`, `abstain_rate`, `hallucination_rate`, `retrieval_hit_rate`, `blocked_rate`, `score`
  → Langfuse 실험 목록에서 시험끼리 **지표를 나란히 비교**할 수 있다.

실행이나 채점이 실패한 문제(API 오류 등)는 집계에서 빼고, 몇 개를 뺐는지 출력한다.

## 결과: 94문제 전체 시험 (`baseline`, 2026-10-20)

나중에 비용을 감수하고 실행했다 (`uv run bnb2 eval baseline`).

| 지표 | bnb2 | 이전 n8n 봇 |
|---|---|---|
| 정답률 | **22.3%** | 36.2% |
| 부분정답률 | 19.1% | 30.9% |
| 오답률 | 11.7% | 9.6% |
| 보류율 | **46.8%** | 23.4% |
| 검색 적중률 | 39.4% | 45.7% |
| 환각률 | **1.1%** (1건) | 측정 안 함 |
| 차단율 | 39.4% | – |
| 종합 점수 | 31.9점 | 51.6점 |

### 원인 분석

**보류 44건 (46.8%)**
| 원인 | 건수 | 뜻 |
|---|---|---|
| 사람 판단 질문 (`escalate`) | 7 | 설계대로. 환불·예약 변경 등 |
| 문서에 답이 없음 (지식 갭) | 27 | 검색된 문서에 정답 정보가 없어 "찾지 못했어요" — 막아야 할 것을 막음 |
| **답이 있었는데 막음 (과잉 차단)** | **10** | 검색된 문서에 정답이 있었지만 근거 검사(`direct`)가 너무 엄격해 막음. 예: "체크아웃 후 밤 비행기면 짐 맡길 수 있나요?" → 정답 "네, 가능합니다" |

**오답 11건 (11.7%)** — 11건 모두 `retrieval_hit=false`. 봇은 **문서대로** 답했는데, 문서가 호스트의 과거 답과 다르다.
- 정책이 바뀐 경우: 짐 보관 15시(과거 답) vs 14:30(현재 문서)
- 문서와 과거 답이 다른 경우: 홍대입구역 5번 출구(문서) vs 6번 출구(과거 답), 11시 vs 11시 10분
- 호스트가 답 대신 되물었던 경우: "주소 알려주세요" → 과거 답 "준비하겠다", 봇은 실제 주소를 답함

**환각 1건 (1.1%)**: "배달 음식 쓰레기는?" → 봇이 "배달 음식도 음식물 쓰레기라면 같은 방법"이라고 문서에 없는 추론을 덧붙였다.

### 해석

- 환각을 막는 장치는 효과가 있다 (환각 1.1%, 오답의 원인은 모델이 아니라 문서·정답지).
- 대신 **너무 보수적이다**. 이전 봇은 애매하면 답했고, bnb2는 애매하면 "찾지 못했어요"라고 한다. 그래서 정답률이 낮고 보류율이 높다.
- 개선 여지가 분명한 곳
  1. 과잉 차단 10건: `direct` 판정 완화 (핵심 질문에 답했으면 통과)
  2. 지식 갭 27건: 문서 보강 (교통·오시는 길 25문제 중 정답 16%로 가장 약함)
  3. 정답지 정리: 정책이 바뀐 과거 답(15시 등) 수정, 5번/6번 출구처럼 문서와 다른 답 확인
