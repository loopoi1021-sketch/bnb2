# 2단계: 문서 적재 (ingest)

> **ingest = kb의 정리된 문서를 가져와서 → 청크로 나누고 → 임베딩해서 → pgvector에 넣는 과정.**
> RAG의 "인덱싱 파이프라인"이다. 질문할 때마다가 아니라 **문서를 고쳤을 때만** 실행한다.

```
uv run bnb2 ingest
   ├─ ① 읽기 + 청킹   load_chunks → chunk_markdown   kb/*.md 7개 → 청크 55개
   ├─ ② 임베딩        embed_documents                55개 → Voyage voyage-4 → 벡터 55개 × 1024
   └─ ③ 저장          save                           pgvector chunks 표 비우고 55줄 넣기
```

## 한 일

| 파일 | 설명 |
|---|---|
| `kb/` | 실제 숙소 문서 7개 (기존 `bnb`에서 복사, **git 제외** — 주소·와이파이 포함) |
| `kb.example/` | 공개용 견본. 개인정보 부분만 다름. `kb/`가 없으면 이걸로 동작 |
| `src/bnb2/ingest.py` | 청킹, 임베딩, 저장 |
| `src/bnb2/__init__.py` | `uv run bnb2 ingest` 명령 연결, `.env` 읽기 |
| `tests/test_ingest.py` | 청킹 규칙 자동 확인 |
| 추가 라이브러리 | `voyageai`(임베딩), `psycopg`(Postgres 접속), `python-dotenv`(`.env` 읽기), `pytest`(테스트) |

## 문서(kb)는 어디서 왔나

기존 `bnb` 프로젝트에서 만든 것을 복사했다.

1. 호스트가 게스트에게 보내던 **입실 안내 메시지**를 → LLM(Claude)이 주제별 `## 항목`으로 재구성 → 호스트가 내용 추가·검토 (41개 항목)
2. **2026년 6월까지의 실제 호스트 답변 419건**을 Claude가 분석해 자주 묻지만 빠진 항목을 제안 → 반영 (55개)

시험지(6단계)는 **7월 이후 질문**만 쓴다. 문서 보강과 시험 기간을 나눠서, 시험 답이 문서에 미리 들어가는 **데이터 누수**를 막았다.

> 실제 회사에서도 흩어진 공지·메신저 답변을 주제별 문서로 정리하는 "지식베이스 구축"을 먼저 한다. 이 문서는 이미 그렇게 정리돼 있어서 섹션 단위 청킹이 잘 맞는다.

## 청킹

### 규칙: `## 항목` 하나 = 청크 하나, 오버랩 없음

입력과 출력 (`kb.example/07_퇴실_안내.md`)

```python
chunk_markdown(
  name='07_퇴실_안내.md',
  text='# 퇴실 안내\n\n## 퇴실 전 할 일\n사용하신 수건은 ...\n\n## 퇴실할 때\n퇴실 시간은 오전 11시입니다. ...\n',
)
→ [
  {'id': '07_퇴실_안내.md#퇴실 전 할 일',
   'source': '07_퇴실_안내.md > 퇴실 전 할 일',
   'content': '퇴실 안내 - 퇴실 전 할 일\n사용하신 수건은 ...'},
  {'id': '07_퇴실_안내.md#퇴실할 때',
   'source': '07_퇴실_안내.md > 퇴실할 때',
   'content': '퇴실 안내 - 퇴실할 때\n퇴실 시간은 오전 11시입니다. ...'},
]
```

| 필드 | 용도 |
|---|---|
| `id` | DB에서 줄을 구분하는 고유 이름 |
| `source` | 슬랙 답변의 📄 출처에 표시 |
| `content` | 임베딩하는 글이자 Claude에게 주는 원문 |

### 왜 섹션 단위, 오버랩 없음인가

**오버랩**은 문서를 글자 수로 기계적으로 자를 때, 앞 조각의 끝을 다음 조각 앞에 겹쳐 넣어 문장이 끊겨도 의미가 살게 하는 장치다.

| 오버랩 장점 | 오버랩 단점 |
|---|---|
| 글자 수로 자를 때 경계에서 문장이 끊겨도 의미가 살아 있음 | 같은 내용이 여러 조각에 중복 → 저장·임베딩 비용 증가 |
| 구조 없는 긴 문서(PDF 규정집 등)에 효과 큼 | 검색 결과에 거의 같은 조각이 2개 나와 자리 낭비 |
| | 크기·겹침 정도를 조정해야 함 |

이 kb는 **이미 주제별 `##`로 나뉘어 있고 항목이 짧다**(최대 207자). 자를 경계가 원래 있으니 문장이 끊길 일이 없고, 오버랩을 넣으면 주제가 다른 항목이 섞이기만 한다. 그래서 섹션 단위로 자르고 오버랩은 쓰지 않았다.

> 구조가 없는 긴 문서였다면 고정 크기(예: 500자) + 오버랩(예: 50~100자)으로 잘랐을 것이다.

### 왜 제목을 붙여서 임베딩하나

`content` = `문서 제목 - 항목 제목` + 본문. **본문에 주제 단어가 빠진 항목을 위한 대비책**이다. 예를 들어 "1인당 2장씩 준비돼 있어요"만으로는 무엇이 2장인지 벡터에 드러나지 않지만, "객실 비품 - 수건"을 붙이면 "수건 몇 장?"과 가까워질 것으로 기대한다.

실제로 재 보니, 본문에 이미 주제가 있는 항목에서는 차이가 거의 없었다 (Voyage 유사도, 0~1):

| 질문 → "퇴실할 때" 항목 | 본문만 | 제목+본문 |
|---|---|---|
| 체크아웃 몇 시까지예요? | 0.564 | 0.550 |
| 나갈 때 문 잠가야 해? | 0.413 | 0.419 |

본문에 "퇴실 시간은 오전 11시"라고 주제가 이미 있어서 제목이 더해 주는 정보가 없었다. 부작용(글자 10~20자 추가)이 거의 없어서 대비책으로 유지하고, **실제 효과는 6단계에서 94문제로 "제목 있음 vs 없음" 검색 적중률을 비교해 측정한다** (개선 실험 후보).

## 임베딩

| 설정 | 값 | 이유 |
|---|---|---|
| 모델 | Voyage `voyage-4` | Anthropic 권장 임베딩. 기존 `bnb`와 같음 → 비교 가능 |
| 차원 | 1024 | `voyage-4` 기본값 |
| `input_type` | `document` | 문서와 질문(`query`)을 구분해 주면 검색 정확도가 오른다 |
| 호출 방식 | 55개를 **한 번에** | 카드 미등록 시 분당 3회 제한. 한 번에 최대 1,000개까지 가능 |

**임베딩의 기준**은 사람이 정하지 않는다. 모델이 "비슷한 문장은 가깝게, 다른 문장은 멀게" 수십억 쌍으로 학습해 스스로 만든 기준이라 각 숫자의 의미는 해석할 수 없다. 우리가 정하는 것은 **어떤 모델로, 무엇을(제목 포함), 어떤 단위로(청킹)** 임베딩하느냐다. 그래서 3단계에서 검색 결과를 눈으로 확인하고 6단계에서 검색 적중률을 측정한다.

## 저장 (pgvector)

```sql
CREATE TABLE chunks (
  id        text PRIMARY KEY,      -- 07_퇴실_안내.md#퇴실할 때
  source    text NOT NULL,         -- 07_퇴실_안내.md > 퇴실할 때
  content   text NOT NULL,         -- 원문 (사람과 Claude가 읽음)
  embedding vector(1024) NOT NULL  -- 벡터 (검색할 때 컴퓨터가 비교)
);
```

| 결정 | 이유 |
|---|---|
| 적재할 때마다 표를 비우고 전부 다시 넣음 | 55개라 몇 초, 비용 거의 0. 바뀐 것만 고르는 것보다 단순하고, 지운 항목이 DB에 남지 않음. 문서가 수천 개가 되면 바뀐 것만 넣는 방식으로 바꾼다 |
| 벡터 검색 인덱스(HNSW 등) 없음 | 55줄은 전부 비교해도 1ms 미만. 인덱스는 수만 줄 이상에서 의미가 있다 |
| 벡터를 글자(`'[0.1, ...]'`)로 넘김 | `pgvector` 파이썬 패키지 없이 `::vector`로 변환. 의존성 하나 줄임 |

## 🔍 직접 확인

**1) 적재 실행**: `청크 55개 / 임베딩 55개 × 1024차원 / 저장 완료`가 나오면 성공이다.
```bash
uv run bnb2 ingest
```

**2) 표 구조**: `embedding | vector(1024)` 칸이 보이면 성공이다.
```bash
docker compose exec pgvector psql -U bnb2 -c '\d chunks'
```

**3) 저장된 내용**: 원문은 사람이 읽을 수 있지만, 벡터는 숫자뿐이라 의미를 알 수 없다.
```bash
docker compose exec pgvector psql -U bnb2 -c "select id, left(content, 40), left(embedding::text, 45) from chunks where id like '07%'"
```

```

 07_퇴실_안내.md#퇴실할 때     | 퇴실 안내 - 퇴실할 때 / 퇴실 시간은 오전 11시... | [0.017899582,-0.034733493,-0.044839673,...
```

**4) 청킹 테스트**
```bash
uv run pytest -q
```
