# 6-1단계: 시험지 등록 (Langfuse Dataset)

> 봇의 실력을 숫자로 재려면 **같은 문제를 매번 똑같이** 풀려야 한다. 그래서 문제와 정답을 Langfuse에 **시험지(Dataset)**로 등록했다.
> 6-3에서는 이 시험지로 시험을 보고(Experiment), 봇을 고칠 때마다 같은 시험을 다시 봐서 점수 변화를 비교한다.

## 한 일

| 파일 | 설명 |
|---|---|
| `data/testset.jsonl` | 기존 `bnb`의 시험지 복사본 (**git 제외** — 실제 게스트 대화) |
| `src/bnb2/evaluate.py` | 시험지를 Langfuse 항목으로 바꿔 올리기 (`to_item`, `upload`) |
| `src/bnb2/__init__.py` | `uv run bnb2 dataset` 명령 추가 |
| `tests/test_tracing.py` | 원문 메시지가 올라가지 않는지 확인하는 테스트 추가 |

## 시험지는 어디서 왔나

기존 `bnb`에서 만든 것이다.
1. 에어비앤비에서 내려받은 실제 대화 기록에서 **게스트 질문과 그 바로 다음 호스트 답**을 짝지었다.
2. Claude가 짝마다 종류와 주제를 붙이고, 외국어 질문은 **한국어로 정리**했다 (`question_ko`, `answer_ko`).
3. **2026년 7월 이후** 일반 질문 94개를 시험지로 떼어 두었다. 6월까지의 답은 문서(kb) 보강에만 썼다. 이렇게 기간을 나눠서, 시험 답이 문서에 미리 들어가는 **데이터 누수**를 막았다.

| 구성 | |
|---|---|
| 문제 수 | 94 |
| 원래 언어 | 한국어 12, 외국어 82 → 모두 한국어로 정리된 버전 사용 |
| 종류 | 질문 83, 요청 7, 문제 신고 4 |
| 주제 상위 | 교통·오시는 길 25, 짐 보관 16, 주변 정보 14, 체크인 8, 현관·비밀번호 6 |
| 길이 (중간값) | 질문 22자, 정답 37자 |

## Langfuse에 올린 모양

```python
{
  "id": "testset-91",                                      # 다시 올려도 중복 없이 덮어씀
  "input": {"question": "체크아웃 후 짐 보관 서비스를 이용할 수 있나요?"},
  "expected_output": {"answer": "오후 2시까지 가능합니다."},     # 호스트의 실제 답 = 정답
  "metadata": {"topic": "짐 보관", "kind": "question", "at": "2026-07-.."},
}
```

| 결정 | 이유 |
|---|---|
| 원문 메시지(`guest`)와 대화방 ID(`thread`)는 **올리지 않음** | 원문에는 이름이나 연락처가 섞여 있을 수 있다. 한국어로 정리된 질문만으로도 시험에는 충분하다 |
| 질문과 답에도 `mask_text` 적용 | 전화번호, 이메일, `MASK_TERMS`를 가린다. 확인 결과 94문제 중 전화번호와 이메일은 0건이었다 |
| `id`를 `testset-번호`로 고정 | 명령을 다시 실행해도 문제가 중복으로 생기지 않는다 |
| `metadata.topic` | 6-3에서 **주제별 정답률**(예: "교통 질문에 약하다")을 볼 때 쓴다 |

⚠️ `MASK_TERMS`는 비워 둔 상태로 올렸다. "현관·비밀번호" 주제 6문제의 호스트 답에 실제 값이 들어 있다면 그대로 올라갔다. 나중에 `MASK_TERMS`를 채우고 `uv run bnb2 dataset`을 다시 실행하면 같은 id로 덮어써서 가려진다.

## 발견: 정답끼리 다른 경우가 있다

```
testset-91  Q: 체크아웃 후 짐 보관 서비스를 이용할 수 있나요?   A: 오후 2시까지 가능합니다.
testset-90  Q: 체크아웃 후 짐을 맡길 수 있나요?               A: 짐 보관은 15시까지 가능합니다.
```
같은 질문인데 호스트의 실제 답이 **14시와 15시로 다르다.** 날짜나 상황에 따라 다르게 답한 것이다. 실제 데이터라서 생기는 잡음이고, 기존 `bnb` 평가에서도 오답 9개 중 3개가 이런 "정책과 다른 옛날 답" 때문이었다.

→ 이 시험의 점수는 **"호스트가 그때 실제로 한 답과 얼마나 같은가"**이지 절대적인 정답률이 아니다.

### 수정: 퇴실 후 짐 보관 = 오후 2시 30분 (호스트 확인)

찾아보니 퇴실 후 짐 보관 시간이 kb와 시험지 여러 곳에서 엇갈렸다. 호스트가 **현재 정책은 14:30**이라고 확인해서, 문서와 정답을 모두 맞췄다.

| 위치 | 전 | 후 |
|---|---|---|
| `kb/01_입실_퇴실.md > 퇴실 후 짐 보관` (+ `kb.example`) | 오후 3시 | 오후 2시 30분 |
| 시험지 49 | 3시 | 오후 2시 30분 |
| 시험지 60 | 오후 3시 | 오후 2시 30분 |
| 시험지 71 | 오후 3시 | 오후 2시 30분 |
| 시험지 90 | 15시 | 오후 2시 30분 |
| 시험지 91 | 오후 2시 | 오후 2시 30분 |

- 고친 뒤 `uv run bnb2 ingest`(문서 재적재)와 `uv run bnb2 dataset`(시험지 재업로드)을 실행했다. 같은 id라 94문제 그대로 덮어써졌다.
- 봇에게 "체크아웃 후 짐 몇 시까지 맡길 수 있어?"라고 물으면 이제 "오후 2시 30분까지"라고 답한다.
- 시험지 65번("체크인 전에 짐을 맡겨도 되나요?" → "오후 3시까지 보관")은 **입실 전** 질문이라 고치지 않았다. 다만 질문과 답이 살짝 어긋나 있어서 6-2에서 다시 본다.
- 원본(`bnb` 프로젝트의 `kb/`와 `testset.jsonl`)은 고치지 않았다. `bnb2`의 복사본만 고쳤다.

**교훈**: 실제 데이터로 만든 시험지는 **정답 자체를 검토하는 과정**이 필요하다. 정책이 바뀌면 문서와 시험지를 함께 고쳐야 점수가 의미를 가진다.

## 🔍 직접 확인

**1) Langfuse 화면**: https://jp.cloud.langfuse.com 에서 왼쪽 메뉴 **Datasets → `bnb2-testset`**으로 간다.
- 문제 94개가 보인다.
- 하나를 클릭하면 Input(질문), Expected Output(정답), Metadata(주제)가 보인다.

**2) 다시 올려도 중복이 안 생기는지**: 다시 실행해도 Langfuse의 문제 수가 94개 그대로면 정상이다.
```bash
uv run bnb2 dataset
```

**3) 테스트**
```bash
uv run pytest -q
```
