# 8단계: 👍/👎 피드백

> 슬랙 답변 아래 버튼으로 직원이 답을 평가한다. **사람이 매긴 점수**가 Langfuse 대시보드(직원 만족도)에 쌓이고, 원본은 우리 DB에 영구 보관되며, 코멘트가 달린 👎는 담당자에게 DM으로 바로 온다.

## 한 일

| 파일 | 설명 |
|---|---|
| `src/bnb2/slack.py` | 버튼 달기(`reply_blocks`), 버튼 처리, 👎 코멘트 입력 창, 저장(`save_feedback`), 담당자 DM(`notify_owner`) |
| `src/bnb2/feedback.py` | 피드백 원본을 Postgres `feedback` 표에 저장, 목록·CSV 출력 |
| `src/bnb2/graph.py` | `answer()`가 Langfuse 트레이스 ID를 함께 돌려줌 |
| `src/bnb2/dashboard.py` | 위젯 2개 추가: 직원 만족도(👍 비율), 👍/👎 개수 |
| `tests/test_slack.py` | 버튼 값, 버튼 → 감사 표시 교체, 담당자 DM 테스트 |

## 흐름

```
🤖 답변 + [👍 정확해요] [👎 틀렸어요]      ← 버튼 값: {"t": 트레이스 ID, "q": 질문}
        │
   👍 클릭 ─▶ 저장(good) ─▶ 버튼을 "👍 피드백 고마워요 — @누구"로 교체
        │
   👎 클릭 ─▶ 코멘트 입력 창 열기 ─▶ 저장(bad) ─▶ 버튼 교체
                    │
              코멘트 쓰고 보내기 ─▶ 저장(bad + 코멘트) ─▶ 담당자 DM
```

### 저장은 두 곳에

| 저장 위치 | 내용 | 용도 | 보관 |
|---|---|---|---|
| **Langfuse 점수** `user_feedback` | 👍=1, 👎=0, 코멘트(개인정보 가림) | 대시보드 차트, 트레이스 화면에서 그 답이 어떻게 나왔는지 보기 | **30일** (무료 플랜) |
| **우리 DB** `feedback` 표 | 질문, 봇 답변, 👍/👎, 코멘트, 누른 사람, 시각, Langfuse 링크 | 원본 영구 보관, 목록, CSV | 영구 |

**DB에 따로 두는 이유**: 피드백은 "문서를 어떻게 고칠지"의 근거라서 오래 남겨야 한다. Langfuse 무료 플랜은 30일이 지나면 지운다. 이미 켜 둔 pgvector DB(Postgres)에 표만 추가해서 새 서비스나 계정이 필요 없다.

```sql
CREATE TABLE feedback (
  trace_id text, slack_user text, good boolean, comment text,
  question text, reply text, trace_url text, created_at timestamptz, updated_at timestamptz,
  PRIMARY KEY (trace_id, slack_user)   -- 같은 사람이 같은 답에 다시 누르면 덮어씀
)
```

### 설계 결정

| 결정 | 이유 |
|---|---|
| 버튼에 트레이스 ID를 담음 | 버튼을 누를 때 "어느 답변에 대한 평가인지"를 Langfuse 트레이스와 정확히 연결한다 |
| 점수 ID = `트레이스ID-사용자` | 같은 사람이 👍→👎로 바꾸거나 코멘트를 더해도 중복이 생기지 않고 덮어쓴다 |
| 👎는 창을 열자마자 0점 저장 | 코멘트 창을 그냥 닫아도 👎는 남는다 |
| 코멘트 없이 다시 저장해도 기존 코멘트 유지 | `COALESCE(새 코멘트, 기존 코멘트)` |
| 입력 창을 버튼 처리보다 먼저 연다 | 슬랙의 `trigger_id`는 3초 안에 써야 한다 |
| 누르면 버튼을 감사 표시로 교체 | 중복 클릭 방지, 누가 평가했는지 보임 |
| **코멘트 있는 👎만** 담당자 DM | 👍나 코멘트 없는 👎까지 오면 알림이 너무 많다. 고칠 거리가 있는 것만 받는다 |
| 오류 답변(⚠️)에는 버튼 없음 | 평가할 답이 없다 |

### 담당자 DM 모양
```
👎 피드백이 왔어요 — @직원
❓ 질문: 담배 어디서 피워야해?
🤖 봇 답변: 문서에서 찾지 못했어요. 담당자에게 확인 후 알려드릴게요.
💬 코멘트: (직원이 쓴 내용)
🔗 Langfuse에서 자세히 보기
```

## 대시보드 위젯 추가

| 위젯 | 조건 |
|---|---|
| 직원 만족도 (👍 비율) | 점수 `user_feedback`의 평균 (1 = 100%) |
| 👍/👎 개수 | 점수 `user_feedback`를 값(1/0)별로 개수 |

## 실제 확인

- 첫 테스트에서 👍 1개, 👎 1개가 Langfuse에 들어왔다 → 만족도 0.5.
- 👎를 받은 질문 "담배 어디서 피워야해?"의 트레이스를 보니, 봇은 "흡연 금지"는 찾았지만 **흡연 가능한 장소는 문서에 없어서** `direct: false` → "찾지 못했어요"였다. **피드백 → 트레이스 → 문서 보강 포인트 발견**의 흐름이 실제로 동작했다.
- 그래서 하우스룰 문서를 고쳤다 (`kb/04_하우스룰.md > 흡연·염색 금지`, `kb.example`도 같이).
  - 전: "흡연 및 염색은 절대 금지입니다. 위반 시 클리닝 비용이 청구됩니다."
  - 후: "**숙소 안에서의** 흡연 및 염색은 절대 금지입니다. 위반 시 클리닝 비용이 청구됩니다. **담배는 숙소 밖에서 피워 주세요.**"
  - "절대 금지"와 "밖에서 피우라"가 서로 어긋나 보이지 않게 "숙소 안에서의"를 붙였다.
  - `uv run bnb2 ingest` 뒤 같은 질문의 답: "찾지 못했어요" → **"담배는 숙소 밖에서 피워 주셔야 합니다. ..."** (`direct: true`)
- DB 저장(덮어쓰기, 코멘트 유지)은 테스트 행으로 확인한 뒤 지웠다. DB 저장을 추가하기 전에 누른 피드백 2개는 Langfuse에만 있다.

## 🔍 직접 확인

**1) 슬랙**: 새 질문 → 👎 → 코멘트 입력 → 봇 DM에 알림이 오는지 확인한다.

**2) 피드백 목록**
```bash
uv run bnb2 feedback
```
```bash
uv run bnb2 feedback --comments
```

**3) CSV로 내보내기**: `data/feedback.csv`가 생긴다. 엑셀이나 구글 시트로 열 수 있다.
```bash
uv run bnb2 feedback --csv
```

**4) Langfuse**: **Dashboards → bnb2 품질** 맨 아래 만족도 차트. 트레이스 화면 맨 위 줄의 `user_feedback` 옆 💬에 코멘트가 보인다.
