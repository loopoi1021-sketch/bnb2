# 10단계: 운영 대시보드

> Langfuse 에서 불편했던 운영 정보를 한 화면에서 본다. 특히 **시험 결과(정답·오답·보류율, 왜 틀렸는지)를 한눈에**.
> 로컬 전용 도구다 (`uv run bnb2 web` → http://127.0.0.1:8000). 포트폴리오에는 화면 캡처를 쓴다.

## 왜 만들었나 — Langfuse 에서 불편했던 것

| 불편 | 이 도구에서 |
|---|---|
| 질문과 답을 한 줄로 훑어볼 수 없다 (트레이스를 하나씩 열어야 함) | **대화** 화면: 질문 · 답 · 결과 · 피드백 · 유사도 · 시간 · 비용을 표 한 줄에 |
| "찾지 못했어요", 차단, 담당자 호출만 모아 보기 어렵다 | **처리함**: 못 한 질문과 👎 만 모아 처리 상태·메모로 관리 |
| 👎 피드백 · 트레이스 · 검색 문서가 따로 논다 | 대화 상세 패널 한 곳에 |
| 시험 실행끼리 비교하기 어렵다 | **시험** 화면: 기준선·다른 시험 대비 증감, 문제별 좋아짐/나빠짐 |
| 왜 틀렸는지 문제마다 채점 이유를 읽어야 한다 | **틀린 이유 자동 분류** + 고칠 곳 |
| 30일 뒤 기록이 지워진다 | 우리 Postgres 에 영구 보관 |
| 영어 UI · 개발자 용어 | 한국어, 운영자 용어 |
| 어떤 문서가 쓰이고 어떤 문서가 놀고 있는지 모른다 | **문서** 화면: 항목별 검색·1위·답에 쓰인 횟수, 한 번도 검색 안 된 항목 |

## 설계 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 데이터 | 봇이 답할 때 **질문 1건 = 1행**을 우리 DB 에 기록. 대시보드는 Langfuse API 를 부르지 않는다 | 빠르고, 영구 보관되고, SQL 로 원하는 집계를 바로 한다. Langfuse 는 상세 트레이스 링크로만 |
| 화면 | FastAPI(JSON API) + React · Vite · TypeScript · Tailwind v4 · shadcn/ui · Recharts | 다듬어진 컴포넌트로 깔끔한 화면이 기본으로 나온다. 빌드한 화면을 FastAPI 가 같이 서빙해서 실행은 명령 하나 |
| 접속 | 이 컴퓨터(127.0.0.1)만. 로그인 없음 | 게스트 질문 원문이 들어 있다. 밖으로 열 거면 로그인부터 |
| 기록 대상 | 슬랙 · CLI 질문만. 시험 94문제는 시험 표에만 | 시험이 운영 지표(질문 수, 해결률)를 오염시키지 않게 |
| 기록 실패 | 답변은 그대로 나간다. 로그만 남긴다 | 기록 때문에 봇이 멈추면 안 된다 |
| 토큰 · 비용 | 구조화 출력에 `include_raw=True` 로 토큰 수를 받고, 코드의 가격표(`graph.PRICE`)로 계산 | Langfuse 없이도 비용을 본다. Langfuse 가 계산한 값과 일치 확인 ($0.000218 = 1,240 × $0.10 + 188 × $0.50, 100만 토큰당) |
| 노드 시간 | 그래프 노드를 `timed()` 로 감싸 `latency_ms` 칸에 기록 | 노드 코드를 건드리지 않고 6개 노드 모두 |

## 틀린 이유 자동 분류

정답이 아닌 문제를 **채점 결과 필드만으로** 어느 단계 탓인지 나눈다. 위에서부터 먼저 맞는 것.

| 순서 | 원인 | 조건 | 고칠 곳 |
|---|---|---|---|
| 1 | 환각 | `hallucination` | 근거 검사 강화 |
| 2 | 분류 | 문서 질문(`faq`)으로 분류되지 않음 | 분류 프롬프트·기준 |
| 3 | 검색·문서 | `retrieval_hit` 이 false (검색된 4개에 정답 정보가 없음) | 문서에 정보 추가, 또는 검색 개선 |
| 4 | 과잉 차단 | 정답 정보가 검색됐는데 근거 검사가 막음 | 근거 검사 완화 |
| 5 | 답변 생성 | 정답 정보가 검색됐고 막히지도 않았는데 틀림 | 답변 프롬프트 |

검색이 먼저 실패했으면 차단됐어도 **검색 탓**으로 본다. 정보가 없는데 막은 건 근거 검사가 제대로 한 일이기 때문이다.

### baseline 시험(94문제)에 적용한 결과

| 원인 | 문제 수 | 비율 |
|---|---:|---:|
| 검색·문서 | 49 | 67% |
| 과잉 차단 | 10 | 14% |
| 분류 | 7 | 10% |
| 답변 생성 | 6 | 8% |
| 환각 | 1 | 1% |

→ 틀린 문제의 **3분의 2가 문서에 정보가 없거나 검색이 못 찾은 것**이다. 프롬프트보다 **문서 보강**이 먼저다. 주제별로는 "교통·오시는 길"(25문제, 점수 28)이 가장 크다.

## 화면

| 화면 | 구성 |
|---|---|
| 개요 | 지표 6개 (질문 수 · 문서 질문 해결률 · 확인 필요 · 직원 만족도 · 응답 시간 중앙값 · Claude 비용, 이전 기간 대비 증감) · 일별 처리 결과 누적 막대 · 확인이 필요한 질문 목록 · 단계별 응답 시간 · 최근 시험 |
| 대화 | 검색 · 결과/피드백/경로 필터 · 기간 · 페이지. 행을 누르면 오른쪽 패널: 봇의 답 → 직원 피드백 → 처리 과정(분류 이유, 답변 초안, 근거 검사 판정) → 검색된 문서와 유사도(답에 쓴 문서 표시) → 노드별 시간 · 토큰 · 비용 → Langfuse 링크 |
| 시험 | 시험 · 비교 대상 선택 · 지표 8개(비교 대상 대비 증감) · 채점 분포 · 왜 틀렸나(누르면 표가 걸러짐) · 주제별 표 · 문제별 표(위험한 것부터, 다른 시험과 비교하면 좋아짐/나빠짐). 문제를 누르면 **호스트 실제 답 vs 봇 답**을 나란히 |

필터와 선택한 행은 주소(URL)에 남아서, 새로고침하거나 링크를 공유해도 같은 화면이 열린다.

색은 data-viz 규칙을 따랐다: 범주 색은 순서를 고정한 5색(라이트·다크 모두 색약 구분 검증 통과), 채점 결과는 상태색(정답 초록 · 부분 노랑 · 오답 빨강 · 보류 회색)이며 항상 글자와 함께 쓴다.

## 한계

- **슬랙 봇은 아직 새 코드로 돌려 보지 않았다.** 기록 코드는 CLI 와 같지만, 실제 슬랙 질문이 들어와 기록되는지 한 번 확인해야 한다.
- 예전 시험 결과에는 실행 시각(파일 수정 시각으로 대신), 커밋, 검색 문서가 없다. 다음 시험부터 남는다.
- Langfuse 에서 가져온 16건은 Langfuse 로 보낼 때 마스킹된 값이다.
- 질문당 비용은 Claude 답변(Haiku)만이다. 채점(Sonnet), 임베딩(Voyage)은 빠져 있다.
- 처리함은 최근 200건까지만 보여준다. 처리 대기가 그보다 쌓이면 페이지 나누기를 붙인다.
- 문서 집계는 대화 전체를 파이썬으로 센다. 대화가 수만 건을 넘으면 SQL(`jsonb_array_elements`)로 옮긴다.
- 문서를 다시 적재(`bnb2 ingest`)하면서 이름이 바뀐 항목은, 예전 대화에서 검색된 기록이 새 항목에 이어지지 않는다.
- 시험지에 추가할 때 `kind` 는 항상 `question` 이다 (요청·문제 유형은 파일에서 직접 고친다).

## 2차: 처리함 · 문서

### 설계 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 처리함에 들어가는 질문 | 찾지 못함 · 담당자 호출 · 오류, 또는 직원이 👎 를 누른 것 | 개요의 "확인 필요"와 같은 조건 (`api.INBOX` 하나로 공유) |
| 처리 상태 저장 | 새 표 `conversation_reviews` (대화 1건 = 1행: 상태 · 메모 · 시험지 번호). 행이 없으면 미처리 | `conversations` 는 봇이 남긴 기록 그대로 두고, 사람이 단 것만 따로 |
| 상태 값 | 미처리(`open`) / 문서 보강함(`fixed`) / 무시(`ignored`) | 운영자가 하는 일이 사실상 이 셋. 담당자 배정 같은 건 혼자 쓰는 도구라 뺐다 |
| 시험지에 추가 | 정답을 받아 `data/testset.jsonl` 끝에 한 줄. 번호는 지금 가장 큰 번호 + 1. 같은 질문은 두 번 못 넣는다 (409) | 시험지 원본은 이 파일이다. Langfuse Dataset 은 `uv run bnb2 dataset` 으로 다시 올린다 (화면에 안내) |
| 다시 돌려보기 | `graph.answer()` 를 다시 실행해 새 `conversations` 행(`channel = 'rerun'`, `thread = 'rerun-원래 id'`)으로 기록. Langfuse 에도 같은 세션으로 묶인다 | 문서를 보강한 뒤 같은 질문이 이제 풀리는지 바로 확인 |
| 다시 돌려본 기록과 운영 지표 | 개요(질문 수 · 해결률 · 일별 · 단계별 시간)와 처리함 · 문서 집계에서 뺀다. 대화 화면에서는 경로 "다시 돌려봄"으로 볼 수 있다 | 운영자가 누른 실행이 게스트 질문 수를 부풀리지 않게 |
| 문서별 집계 | `chunks` 표의 항목마다 `conversations.chunks` 에서 검색된 횟수, 1위 횟수, 답에 쓰인 횟수(`sources`, **답이 실제로 나간 경우만**), '찾지 못함' 질문의 1위 횟수 | 근거 검사에 막힌 초안에도 `sources` 가 남아 있어서, 그대로 세면 '쓰였다'가 부풀려진다 |
| 주소 | `/docs` 를 문서 화면이 쓰므로 FastAPI 의 Swagger(`/docs`, `/redoc`)는 껐다 | 둘이 겹치면 Swagger 가 먼저 잡는다 |

## 🔍 직접 확인

```bash
cd web && npm install && npm run build && cd ..   # 화면 빌드 (처음 한 번, 화면을 고친 뒤)
uv run bnb2 backfill                              # 이전 기록 가져오기 (한 번)
uv run bnb2 web                                   # http://127.0.0.1:8000
```

화면을 고칠 때는 `uv run bnb2 web` 을 켜 둔 채로 `cd web && npm run dev` 를 띄우면 저장할 때마다 바로 반영된다 (API 는 8000 번으로 연결).
