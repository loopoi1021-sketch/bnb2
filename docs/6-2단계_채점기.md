# 6-2단계: 채점기 (LLM-as-judge)

> 시험지 문제를 봇에게 풀리고, **더 강한 모델(Claude Sonnet)이 채점**한다.
> 94문제 전체를 돌리기 전에 **5문제만** 돌려서, 채점이 공정한지 사람이 먼저 검토한다. 채점기가 엉터리면 점수 전체가 의미 없기 때문이다.

## 한 일

| 파일 | 설명 |
|---|---|
| `src/bnb2/evaluate.py` | `task`(문제 풀기), `judge`(채점), `sample`(검토용 n문제), `experiment`(시험 실행·저장·출력) |
| `src/bnb2/retrieve.py` | `warm_query_cache`: 시험 질문을 **Voyage 1회 호출로 한꺼번에** 임베딩해 둠 |
| `src/bnb2/__init__.py` | `uv run bnb2 eval 이름 [개수]` 명령 추가 |
| `data/eval-<이름>.jsonl` | 문제별 결과 (git 제외) |

## 시험 흐름

```
uv run bnb2 eval judge-check 5
   ├─ Langfuse 에서 시험지 가져오기 → 주제가 다른 5문제 고르기 (sample)
   ├─ 질문 5개를 Voyage 1회로 임베딩 (warm_query_cache)        ← 분당 3회 제한 회피
   ├─ run_experiment (동시에 4문제씩)
   │    ├─ task : 문제 → 4단계 그래프 실행 → 답변, 분류, 차단 여부, 검색된 청크
   │    └─ judge: 질문 + 호스트 정답 + 봇 답변 + 검색된 청크 → Sonnet 채점 → 점수 4개
   ├─ Langfuse: 문제마다 트레이스 + 점수 기록, 실험(Experiment) 결과 화면 생성
   └─ data/eval-judge-check.jsonl 저장 + 화면 출력
```

## 점수 4개

| 점수 | 종류 | 누가 판정 | 뜻 |
|---|---|---|---|
| `grade` | correct / partial / wrong / abstain | Sonnet | 호스트 실제 답과 비교한 정답 여부 |
| `hallucination` | true / false | Sonnet | 답변에 **검색된 문서에 없는** 정보가 있나 (정답과 무관) |
| `retrieval_hit` | true / false | Sonnet | 검색된 청크 4개 안에 정답의 핵심 정보가 있었나 |
| `blocked` | true / false | 코드 (그래프 결과) | 문서 질문인데 근거 검사 노드가 답을 막았나 |

이 점수로 6단계 지표를 계산한다: 정답률 = correct 비율, 오답률 = wrong 비율, 보류율 = abstain 비율, 환각률 = hallucination 비율.

### 채점 지시문 (Sonnet)
```
grade (호스트 정답 기준):
- correct: 정답의 핵심 정보(시간, 장소, 가능 여부 등)가 모두 맞다. 표현이 달라도 된다.
- partial: 핵심 정보 일부만 맞거나 빠진 것이 있다. 틀린 정보는 없다.
- wrong: 정답과 어긋나는 정보가 하나라도 있다.
- abstain: 봇이 답을 주지 않았다 ("문서에서 찾지 못했어요", "담당자 판단이 필요", 인사만 함).
hallucination (<검색된 문서> 기준, 정답과 무관): 문서에 없는 정보가 있으면 true. abstain 이면 항상 false.
retrieval_hit: <검색된 문서> 안에 정답의 핵심 정보가 들어 있으면 true.
```

## 설계 결정

| 결정 | 이유 |
|---|---|
| 채점 모델 `claude-sonnet-5-5` | 답변 모델(Haiku)보다 강한 모델로 채점한다. 기존 `bnb` 채점과 같은 모델이라 비교할 수 있다 |
| 문제당 Sonnet **1회**로 점수 3개 | 따로 부르면 비용이 3배다. 94문제 기준 약 $1 이하 |
| 구조화 출력 `method="json_schema"` | Sonnet 5.5는 기존 방식(도구 호출 강제)을 지원하지 않는다는 경고가 나왔다. 권장 방식으로 바꿨다 |
| `max_concurrency=4` | 동시에 4문제씩. API 한도에 걸리지 않을 정도로 |
| 질문 미리 임베딩 | Voyage 무료 한도(분당 3회) 때문. 94문제를 하나씩 하면 30분 이상, 묶으면 1회 |
| `blocked`는 코드로 판정 | 그래프가 이미 아는 사실(grounded, direct)이라 LLM이 필요 없다 |

## 5문제 결과 (`judge-check`)

| 문제 | 주제 | 봇 답변 요약 | grade | 환각 | 검색 적중 | 차단 |
|---|---|---|---|---|---|---|
| 93 현관문 비밀번호는 어떻게 누르나요? | 현관·비밀번호 | 생일로 설정한 번호를 도어락에 누르세요 | partial | ❌ | ❌ | ❌ |
| 92 공항 픽업이 숙소 앞까지 가나요? | 교통 | 홍대입구역에서 내리세요. 픽업 정보는 문서에 없음 | partial | ❌ | ❌ | ❌ |
| 91 체크아웃 후 짐 보관 되나요? | 짐 보관 | 오후 2시 30분까지, 무료 | **correct** | ❌ | ✅ | ❌ |
| 88 체크인 전 짐 맡길 수 있나요, 몇 시간 전에 연락? | 주변 정보 | 오전 11시부터 가능. 연락 시점은 문서에 없음 | partial | ❌ | ❌ | ❌ |
| 86 서울숲 공원 개방했나요? | 기타 | 문서에서 찾지 못했어요 | abstain | ❌ | ❌ | ✅ |

### 채점 이유 (Sonnet)
- **93**: "정답의 핵심인 '비밀번호 입력 후 **V 버튼**을 누른다'는 내용이 빠졌다. 틀린 정보는 없다. 검색된 문서에는 V 버튼 정보가 없다."
- **92**: "홍대입구역에서 내리라는 건 정답과 모순되지 않지만, 직접 와야 한다는 핵심(픽업 없음)과 짐보관 정보는 빠졌다."
- **91**: "오후 2시 30분까지 가능하다고 답했고 정답과 일치한다. 무료라는 추가 정보도 검색된 문서에 있다."
- **88**: "짐 보관이 가능하다고 맞게 답했지만, 정답의 핵심인 '도착해서 입구 앞에서 메시지를 남기면 된다'는 내용이 없다."
- **86**: "봇이 '문서에서 찾지 못했어요'라며 답을 주지 않았다. 검색된 문서에 서울숲 정보가 없다."

## 검토 메모

1. **채점은 대체로 납득된다.** 틀린 정보가 없고 핵심이 빠진 경우는 partial, 일치하면 correct, "찾지 못했어요"는 abstain으로 일관되게 판정했다.
2. **환각 0건.** 5문제 모두 답변 내용이 검색된 문서 안에 있었다. 문서에 없는 서울숲 질문은 근거 검사가 막았다(`blocked`).
3. **partial 3건의 원인은 대부분 "문서에 정보가 없음"이다.** V 버튼, 공항 픽업 여부, 도착 시 연락 방법은 kb에 아예 없다. 봇이나 검색이 잘못한 게 아니라 **지식 갭**이다.
4. 그런데 지금 `retrieval_hit=false`는 **"문서에는 있는데 검색이 못 찾음"과 "문서에 아예 없음"을 구분하지 못한다.** 고칠 곳이 다르다 (검색 개선 vs 문서 보강).
5. 92번처럼 "픽업 정보는 문서에 없어 확인해 드리기 어렵습니다"를 섞은 답이 `direct` 검사를 통과했다. 질문 일부(어느 역에서 내리나)에는 직접 답했기 때문이다.
6. 88번은 시험지의 주제 분류가 "주변 정보"로 잘못 붙어 있다 (실제는 짐 보관). 이전 세션의 자동 분류 오류다.

## 검토 결과

호스트가 5개 채점 결과에 **동의**했다. 이 채점 기준으로 6-3 전체 시험을 진행한다.

## 답변 고치는 방법 (운영 루프)

봇 답변은 매번 새로 생성되므로 답 자체를 고치지 않는다. **답을 만드는 재료나 지시**를 고친다.

| 고치는 곳 | 언제 | 파일 |
|---|---|---|
| 문서 (kb) | 답의 **내용**이 없거나 틀릴 때 | `kb/*.md` → `uv run bnb2 ingest` |
| 검색 설정 | 문서엔 있는데 **못 찾을 때** | `retrieve.py`의 `TOP_K` 등 |
| 답변 지시문 | 내용은 맞는데 **말투, 길이, 형식**이 별로일 때 | `graph.py`의 `GENERATE_PROMPT` |

```
시험 → 틀린 문제 확인 → 원인 찾기 → 고치기 → 다시 시험 → 점수 비교
```

### 적용 예: 93번 "현관문 비밀번호는 어떻게 누르나요?"

- **원인**: 정답의 핵심인 "V 버튼"이 문서에 없었다 (지식 갭).
- **수정**: `kb/01_입실_퇴실.md > 현관 비밀번호`에 한 줄을 추가했다 (`kb.example`에도 같이 추가).
  > 도어락에 비밀번호를 누른 뒤 V 버튼을 누르면 문이 열립니다.
- `uv run bnb2 ingest`로 문서를 다시 넣은 뒤 같은 질문을 했다.

| | 봇 답변 |
|---|---|
| 전 (partial) | 현관 비밀번호는 게스트마다 새로 설정됩니다. ... 그 번호를 전자 도어락에 눌러 입장하시면 됩니다. |
| 후 | **도어락에 비밀번호를 누른 뒤 V 버튼을 누르면 문이 열립니다.** 현관 비밀번호는 게스트마다 새로 설정되며, 입실 안내 메시지로 보내드립니다. |

⚠️ **시험 문제를 보고 문서를 고치면 점수가 부풀려질 수 있다** ("시험 답을 보고 공부한" 셈). 그래서 9단계 개선 실험에서는 시험지를 **개선용**과 **최종 확인용**으로 나눈다. 이번 수정은 호스트가 확인한 실제 정보라 문서에 남겼다.

## 🔍 직접 확인

**1) 같은 시험 다시 돌리기**: 결과가 조금씩 달라질 수 있다. LLM은 매번 똑같이 답하지 않는다.
```bash
uv run bnb2 eval judge-check2 5
```

**2) Langfuse 화면**: 왼쪽 메뉴 **Datasets → bnb2-testset → Runs(Experiments)**에서 `judge-check` 실행을 연다.
- 문제마다 봇 답변과 점수(grade, hallucination, retrieval_hit, blocked)가 표로 보인다.
- 행을 클릭하면 그 문제의 트레이스(노드별 기록)로 이동한다.
- grade 점수에 마우스를 올리면 채점 이유(comment)가 보인다.
