# 3단계: 검색 (retrieve)

> 질문을 **Voyage로 임베딩**하고, **pgvector에서 가장 가까운 청크 4개**를 찾는다. 아직 Claude는 쓰지 않는다. RAG의 "R(Retrieval)" 부분이다.

```
"수건 더 있어요?" ──Voyage(query)──▶ 질문 벡터 1개
                                         │
                       pgvector: chunks 55줄과 거리 비교 → 가까운 순 4개
                                         ▼
               [0.614] 05_객실_구성과_비품.md > 수건 ...
```

## 한 일

| 파일 | 설명 |
|---|---|
| `src/bnb2/retrieve.py` | `embed_query` (질문 임베딩), `search` (SQL로 top-k) |
| `src/bnb2/__init__.py` | `uv run bnb2 search "질문"` 명령 추가 |

## 핵심 코드

```python
def search(question, k=4):
    vec = str(embed_query(question))       # 질문 → 벡터 (input_type="query")
    SELECT id, source, content, 1 - (embedding <=> 질문벡터) AS score
    FROM chunks ORDER BY embedding <=> 질문벡터 LIMIT 4
```

| 설정 | 값 | 이유 |
|---|---|---|
| 질문 임베딩 | `voyage-4`, `input_type="query"` | 문서와 **같은 모델**이어야 같은 '의미 지도'에서 비교된다. `query`/`document`를 구분하면 정확도가 오른다 |
| `<=>` | 코사인 거리 (pgvector 연산자) | 0이면 같은 방향(같은 의미), 클수록 멀다 |
| `score` | `1 - 코사인 거리` = 코사인 유사도 | 사람이 읽기 쉽게 "1에 가까울수록 비슷함"으로 바꿈 |
| top-k | **4** | 기존 `bnb`와 같음 → 비교 가능. 6단계 측정 후 조정 |
| 점수 기준값(threshold) | **없음** | 아래 "발견" 참고. 기준값으로 거르지 않고 4번 근거 검사 노드에서 판단 |
| 인덱스 | 없음 (전부 비교) | 55줄은 1ms 미만 |

## 실제 검색 결과

### ① "체크아웃 몇 시까지예요?" — 답이 있는 질문
```
[1] 0.579  01_입실_퇴실.md > 퇴실 시간              ✅ 정답
[2] 0.564  01_입실_퇴실.md > 얼리 체크인·레이트 체크아웃
[3] 0.551  07_퇴실_안내.md > 퇴실할 때               ✅ 이것도 정답 포함
[4] 0.532  01_입실_퇴실.md > 입실 시간
```
"체크아웃"이라는 단어는 문서에 없지만 **"퇴실"을 찾았다**. 글자가 아니라 의미로 찾는 임베딩 검색의 효과다. 다만 1등과 4등 차이가 0.047로 **촘촘하다**.

### ② "수건 더 있어요?" — 답이 있는 질문
```
[1] 0.614  05_객실_구성과_비품.md > 수건             ✅ 정답, 2등과 차이 큼
[2] 0.480  05_객실_구성과_비품.md > 다리미·빨래 건조대
[3] 0.468  05_객실_구성과_비품.md > 침구
[4] 0.404  05_객실_구성과_비품.md > 욕실 용품
```

### ③ "근처에 맛집 추천해줘" — **문서에 답이 없는** 질문
```
[1] 0.492  06_주차와_주변.md > 카페                 ❌ 맛집 정보 아님
[2] 0.459  06_주차와_주변.md > 편의점·올리브영
[3] 0.379  06_주차와_주변.md > 주변 거리
[4] 0.334  04_하우스룰.md > 요리
```

## 발견: 검색은 "답이 없어도" 항상 4개를 돌려준다

- 벡터 검색은 **가장 가까운 것**을 찾을 뿐, "답이 있다/없다"를 판단하지 않는다. ③처럼 답이 없어도 그럴듯한 4개가 나온다.
- **점수로 거르기도 어렵다.** 답이 없는 ③의 1등(0.492)과 답이 있는 ①의 4등(0.532), ②의 2등(0.480)이 비슷한 구간에 있다. "0.5 미만은 버린다" 같은 기준을 두면 정답을 버리거나 오답을 통과시킨다. (기존 `bnb`의 0.3 기준도 검증되지 않은 값이었다.)
- 그래서 설계대로 **"답이 있는지"는 Claude가 판단**한다.
  - ③ 답변 노드: "문서에 없으면 지어내지 말라"
  - ④ 근거 검사 노드: 답변이 실제로 문서에 있는지 다시 확인 → 없으면 "문서에서 찾지 못했어요"

이게 4단계(LangGraph)에 근거 검사 노드를 두는 이유이고, 6단계에서 **환각률**로 효과를 잰다.

## 🔍 직접 확인

```bash
uv run bnb2 search "체크아웃 몇 시까지예요?"
```
```bash
uv run bnb2 search "수건 더 있어요?"
```
```bash
uv run bnb2 search "근처에 맛집 추천해줘"
```

다른 질문도 자유롭게 넣어보면서 **정답 항목이 몇 등으로, 몇 점으로 나오는지** 보면 된다.

⚠️ Voyage 무료 한도는 **분당 3회**다. 1분 안에 4번 이상 검색하면 `RateLimitError`가 난다. 잠시 기다렸다가 다시 하면 된다.
