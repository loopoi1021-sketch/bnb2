# 0단계: 프로젝트 뼈대

## 한 일

| 명령 / 파일 | 설명 |
|---|---|
| `git init -b main` | git 저장소 생성. 단계가 승인될 때마다 커밋 하나씩 남긴다 |
| `uv init --package --python 3.12` | Python 패키지 프로젝트 생성 |
| `.python-version` | 이 프로젝트는 Python 3.12를 쓴다고 uv에 알려줌 |
| `pyproject.toml` | 프로젝트 이름, 필요한 라이브러리 목록, 실행 명령(`bnb2`) |
| `src/bnb2/__init__.py` | 실제 코드가 들어갈 곳. 지금은 인사말만 출력 |
| `.gitignore` | git에 올리지 않을 것: `.env`(키), `.venv`, `kb/`·`data/`(개인정보) |
| `.env.example` | 필요한 키 **이름만** 적은 견본. 단계별로 언제 필요한지 표시 |

## 폴더 구조

```
bnb2/
├── docs/              # 단계별 설명 문서 (지금 읽는 파일)
├── src/bnb2/          # 코드
├── .env.example       # 키 견본 (git에 올라감)
├── .env               # 실제 키 (git 제외, 직접 만듦)
├── pyproject.toml     # 프로젝트 설정 + 라이브러리 목록
└── uv.lock            # 라이브러리 정확한 버전 (라이브러리 추가 시 생김)
```

이후 단계에서 필요할 때 폴더를 추가한다(`kb/`는 2단계, `docker-compose.yml`은 1단계).

## 왜 Python 3.12인가

이 컴퓨터에는 3.14가 깔려 있지만, 3.14는 나온 지 1년 정도라 일부 라이브러리(DB 드라이버 등)가 아직 완전히 지원하지 않을 수 있다. 3.12는 LangGraph·Langfuse·Voyage가 모두 확실히 지원하는 버전이다. uv가 3.12를 자동으로 내려받아서 이 프로젝트에만 쓴다.

## 왜 `--package`인가

코드를 `src/bnb2/` 안에 두는 구조. 나중에 `uv run bnb2 ask "질문"`처럼 명령어로 실행할 수 있고, 테스트가 실수로 설치 안 된 코드를 불러오는 일을 막아준다.

## 🔍 직접 확인

```bash
uv run bnb2
```
→ `Hello from bnb2!` 가 나오면 성공.

```bash
cat .env.example
```
→ 앞으로 필요한 키 목록. 지금 미리 발급받아 두면 좋은 것: **Anthropic, Voyage** 키.
